# 测试体系

> 面向:为本工程添加或修改测试的开发者。
> 定位:建立正确的测试心智模型——测什么、在哪测、怎么断言。读完能判断"这个改动该加什么测试、加在哪一层"。

## 一、为什么是四层(一段教训)

v0.3.2 之前,409 个单元测试全绿,却挡不住 Tab 键"第二次创建推飞画布"的 bug。诊断结论是**金字塔倒挂**:单元层 409 个,画布交互层 0 个,端到端 0 个。根因有二:交互逻辑内联在组件闭包里不可测;jsdom 没有真实布局,画布物理上跑不起来。

测试重构按四层补齐,每一层解决一个明确的问题:

| 层 | 位置 | 解决什么 | 数量 |
|---|---|---|---|
| L1 纯函数 | `src/**/*.test.ts`(jsdom) | 交互决策与几何计算脱离组件,穷举可测 | 429 |
| L2 测试基建 | `src/testing/` + `?testMode=1` | 真浏览器里跑完整应用,绕开 jsdom 无布局 | — |
| L3 旅程矩阵 | `e2e/*.spec.ts`(Playwright) | 用户旅程级回归,九族覆盖 | 32 |
| L4 质量门 | pre-push + CI | 上述一切自动强制,不靠自觉 | — |

**判断新测试放哪层**:逻辑可纯化(输入→输出)→ L1;涉及真实布局/渲染 → L3;两者之间优先 L1(快且稳定),L3 只留用户能感知的旅程。

## 二、三条断言纪律(全矩阵统一遵守)

这三条是从真实 bug 里换来的,写用例前必须知道:

**1. 视图零变化 = 锚点节点视口 rect 恒定,不是 canvas transform。**
位置保持补偿(`keepAnchorInPlace`)的本质就是修改 transform 抵消库的推飞——transform 必然变化,而锚点纹丝不动。断言 transform 会假绿,断言锚点 rect 才是真话。(Tab 后 transform 从 `616,99.5` 变 `616,49.75` 而锚点 drift=0,是这条纪律的实证。)

**2. 布局零位移 = 状态栏与工具栏 rect 恒定。**
浮层(Portal 挂 body)不参与文档流,它的出现不得挤压任何布局。这是浮层劫持家族 bug(三轮才根治)的运行时守护。

**3. 创建断言与视图断言双保险。**
内容操作用例必须同时断言"操作生效"(节点数/文本)和"视图未动"(锚点 rect)——只测前者会漏推飞,只测后者会漏不创建。

## 四、L2 基建如何工作(原理,不抠细节)

`?testMode=1` 时,`main.tsx` 最先安装 mock 的 `window.__TAURI_INTERNALS__`——`isTauri()` 与全部 `invoke`/`listen` 因此走 mock:29 个命令由内存表分发(文档/配置/保存/导出管道全通),事件通道可派发(菜单动作、LLM 会话广播)。应用不知道自己在被测试,**生产代码零感知、零改动**。

预置文档是一棵深树(11 节点、深度 3)——树深 ≥3 才会触发 5.14 layout 推飞,浅树会让键盘族用例静默绕过当年 bug 的现场,形成假绿。改 mock 数据时保住这条底线。

断言钩子:`window.__testMock`(调用记录/内存文件系统/`emit`/`emitMenuAction`)。E2E 里用它读管道真相(如 `callsOf("save_mmap")`),不依赖 UI 呈现。

## 五、九族矩阵速览

| 族 | 文件 | 守护对象 |
|---|---|---|
| 键盘(6) | `keyboard.spec.ts` | Tab 双变体/Enter/F2/Delete/焦点环接管 |

| 数据(3) | `data.spec.ts` | undo/redo/自动保存一致性 |
| MCP 协作(3) | `mcp.spec.ts` | 会话横幅/画布锁定/接管中断权 |
| 搜索跳转(3) | `search.spec.ts` | 显式跳转例外正确地是例外 |

**加用例的模板**:gotoMap → 记录锚点/布局指纹 → 操作 → 双保险断言。工具函数全在 `e2e/helpers.ts`。

## 六、质量门

- **本地 pre-push**:eslint → tsc → vitest(429) → playwright(32) → cargo → MCP 覆盖率(95% 门禁),六级全绿才可推送;
- **CI(GitHub Actions)**:同一套检查在远端独立复验(fe / rust+coverage / e2e 三 job)——本地钩子可绕过,CI 不可。E2E 跑在 ubuntu(testMode 不依赖 Tauri 运行时,这是 L2 基建最大的红利)。

## 七、历史教训索引(写测试前值得一读)

- **假绿**:浅树绕过推飞路径;transform 断言漏掉补偿;矩阵须自证(注入 bug 必须变红,v0.3.2 时 kb-01 注入后捕获 691px 推飞);
- **矩阵抓到的真实缺陷**:undo"没反应"(撤销栈混入仅选中变化条)、"每按两次退一步"(undo 回流污染历史)——均为 429 单测时代不可见的交互层缺陷;
- **vitest browser mode 改道**:4.1.11 provider 加载缺陷,几何测试改由 Playwright 承担(决策记录在 `vitest.config.ts` 注释)。
